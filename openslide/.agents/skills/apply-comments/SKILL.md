# Правки по комментариям к слайдам

Инспектор редактора OpenSlide позволяет выбрать отображаемый элемент и оставить текстовый комментарий, например «сделай красным» или «замени на “OpenSlide — отличный инструмент”». Комментарий сохраняется как JSX-маркер в исходном файле `slides/<slideId>/index.tsx`.

Прочитай маркеры, внеси указанные изменения и удали обработанные маркеры.

> **Перед любым изменением слайда** прочитай **`slide-authoring`**: устройство `slides/<id>/index.tsx`, рабочая область, размеры шрифта, палитра, ресурсы и требования к файлу. Даже правки «увеличь» или «смени акцентный цвет» должны соответствовать этим правилам.

## Формат маркера

```
{/* @slide-comment id="c-<8hex>" ts="<ISO>" text="<base64url(JSON)>" */}
```

- Маркер всегда занимает отдельную строку и находится **первым дочерним узлом внутри** соответствующего JSX-элемента: после открывающего `>` и перед остальным содержимым. Маркер размещён внутри целевого элемента, а не над ним.
- `text` — JSON в кодировке base64url: `{"note": "...", "hint"?: "..."}`.
- Для поиска используй в точности это регулярное выражение:

  ```
  /\{\/\*\s*@slide-comment\s+id="(c-[a-f0-9]+)"\s+ts="([^"]+)"\s+text="([A-Za-z0-9_\-]+={0,2})"\s*\*\/\}/g
  ```

## Порядок работы

1. **Определи презентации для правок.**
   - Если пользователь назвал одну (`getting-started`, `q2-roadmap` и т. п.), работай только с её `slides/<slideId>/index.tsx`.
   - Если указано «все» или конкретная презентация не названа, проверь все `slides/*/index.tsx`. Обрабатывай презентации по очереди.

2. **Прочитай файл и найди все маркеры.**
   - Примени регулярное выражение выше ко всему файлу.
   - Для каждого совпадения декодируй `text` из base64url и выполни `JSON.parse`, чтобы получить `{ note, hint? }`.
   - Сохрани `{ id, lineIndex (нумерация с 0), note, hint }`.
   - Если маркеров нет, сообщи пользователю и остановись.

3. **Разбери каждый комментарий в контексте.**
   - Цель — JSX-элемент, **внутри которого** находится маркер. Читай вверх до незакрытого открывающего JSX-тега, содержащего маркер. Для самозакрывающихся элементов вроде `<img />` инспектор переносит маркер в ближайшего несамозакрывающегося предка. Тогда комментарий обычно относится к дочернему элементу; уточняй цель по `note`.
   - Прочитай окружающий код: родительский элемент, соседние элементы, встроенные стили. Например, комментарий внутри `<div>` с `background` во встроенном стиле обычно относится к оформлению этого `<div>`.
   - При неоднозначном `note` выбери минимальное разумное толкование и укажи допущение в отчёте.

4. **Вноси правки снизу вверх.**
   - Отсортируй маркеры по убыванию `lineIndex` и обрабатывай по одному инструментом `Edit`.
   - При обработке сверху вниз изменение длины файла сбивает номера строк следующих маркеров.

5. **После правки удали соответствующий маркер.**
   - Удали всю строку маркера вместе с завершающим `\n`.
   - Не оставляй маркер выполненной правки: это означает, что она ещё не обработана. Сознательно пропущенные маркеры оставляй по правилам ниже.

6. **Проверь результат.**
   - Повторно прочитай файл: должны остаться только маркеры, о пропуске которых ты сообщил.
   - Проверь корректность JSX: парные теги, отсутствие лишних атрибутов. Если в `package.json` есть команды проверки типов или стиля, запусти их менеджером пакетов проекта. В проектах из шаблона нет ни TypeScript, ни средства проверки стиля: используй работающий сервер разработки или команду `build` для выявления ошибок компиляции. Исправь внесённые ошибки.
   - Если сервер разработки работает, сделай снимок каждого изменённого слайда через `/s/<id>/preview?p=N`. См. **«Визуальная проверка слайда»** в `slide-authoring`.

7. **Сообщи результат.**
   - Укажи: «Применено: N, пропущено: M» и кратко опиши каждую правку с идентификатором презентации.

## Вспомогательная функция декодирования base64url

```js
function decode(s) {
  const pad = s.length % 4 === 0 ? '' : '='.repeat(4 - (s.length % 4));
  return Buffer.from(s.replace(/-/g, '+').replace(/_/g, '/') + pad, 'base64').toString('utf8');
}
```

Для просмотра содержимого можно вызвать функцию через `node -e '...'`; если это не нужно, работай с декодированной строкой напрямую.

## Особые случаи

- **Маркер вне JSX-элемента**: инспектор не должен создавать такие маркеры, но если такой найден, удали его и сообщи о маркере без целевого элемента.
- **Несколько маркеров подряд внутри одного элемента**: все относятся к этому элементу. Прочитай комментарии в исходном порядке для понимания общего замысла, затем внеси правки и удали маркеры снизу вверх, как на шаге 4.
- **Комментарий выходит за пределы целевого элемента**, например «добавь новый слайд»: внеси ближайшее разумное изменение и укажи расширение объёма работы в отчёте.
- **Комментарий невозможно разрешить**: он совершенно неоднозначен или целевой элемент исчез после изменения файла. Оставь маркер и сообщи о пропуске. Не угадывай.

## Запреты

- Не меняй `package.json`, `open-slide.config.ts` и файлы за пределами `slides/`.
- Не добавляй зависимости.
- Не возвращай удалённые маркеры и не оставляй `TODO`: история изменений уже есть в Git.
