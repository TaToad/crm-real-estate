# Создание темы оформления

Навык создаёт **комплект темы** в `themes/`: два связанных файла, описывающих оформление для повторного использования.

1. `themes/<id>.md` — документация для агента: палитра, типографика, макет, постоянные компоненты `Title`/`Footer`/`Eyebrow`, анимация. Её читает `create-slide` после выбора темы.
2. `themes/<id>.demo.tsx` — исполняемый пример обычного модуля презентации с `export default Page[]`, показывающий оформление на 2–3 слайдах. Панель **Themes** загружает файл для интерактивного предпросмотра.

Имена обоих файлов до расширения совпадают, чтобы движок автоматически связал их.

Тема **отличается от константы `design` в презентации**. Markdown темы задаёт визуальный стиль, который `create-slide` переносит в исходный код презентации. Пример `.tsx` самодостаточен и не появляется в списке презентаций. Объявленный в начале `slides/<id>/index.tsx` объект `const design: DesignSystem = { … }` содержит параметры оформления, которые пользователь меняет в панели Design во время работы. Markdown задаёт стиль, `design` позволяет его настраивать, `.demo.tsx` показывает тему в действии.

Записывай только `themes/<id>.md` и `themes/<id>.demo.tsx`. Не меняй презентации и конфигурацию. Прочитай **`slide-authoring`** до создания темы: там заданы рабочая область и стандартные размеры шрифта. Отклонения от этих значений указывай явно.

## Шаг 1 — Определи исходные материалы

Тему можно создать по любому сочетанию трёх источников:

- **Изображения-образцы** — пути или URL снимков слайдов, подборок визуальных примеров, фирменных материалов.
- **Текстовое описание** — желаемая палитра, шрифты, характер оформления.
- **Существующая презентация** — `slides/<id>/index.tsx`, оформление которой нужно выделить в отдельную тему.

Если источники уже однозначно заданы в запросе, продолжай без вопроса. Иначе вызови `AskUserQuestion` с множественным выбором источников. Уточняй пути, идентификатор презентации или описание только по необходимости.

## Шаг 2 — Собери исходные данные

- **Изображения**: прочитай каждый файл инструментом `Read`, который поддерживает изображения. Отметь основные цвета в HEX, начертание и насыщенность шрифта, ритм макета, декоративные мотивы и повторяющиеся элементы: верхнюю полосу, линию нижнего колонтитула, номера слайдов.
- **Текст**: выдели точные параметры — HEX-коды, названия шрифтов, характер движения — и описание стиля: «журнальный», «игровой», «брутализм». До записи преврати расплывчатые пожелания в конкретные решения.
- **Существующая презентация**: прочитай `slides/<id>/index.tsx` и перенеси:
  - `design.palette` или прежнюю константу `palette` в начале файла — в раздел «Палитра».
  - `design.fonts`, константы шрифтов и закономерности `font-size` — в «Типографику».
  - Отступы и выравнивание — в «Макет».
  - Повторяющиеся компоненты `TrafficLights`, `Eyebrow`, вспомогательные компоненты нижнего колонтитула, `WindowShell` и т. п. — в «Постоянные компоненты».
  - Блоки `@keyframes` и общую строку `styles` — в «Анимацию».
  - Общее впечатление от оформления — в «Визуальный стиль».

При противоречии источников, например синем цвете на изображении и зелёном в описании, уточни приоритет у пользователя.

## Шаг 3 — Выбери идентификатор темы

Короткое, понятное имя в **kebab-case**: `editorial-noir`, `brutalist-mono`, `pastel-soft`, `dev-terminal`. Проверь `themes/`, чтобы избежать совпадений.

## Шаг 4 — Создай `themes/<id>.md`

Соблюдай точный порядок разделов ниже. Содержимое адаптируй к теме, заголовки сохраняй единообразными.

````markdown
---
name: <Понятное название, например «Тёмный журнальный стиль»>
description: <Описание в одну строку>
mode: <dark или light — в соответствии с цветом bg>
---

# <Название темы>

## Палитра

| Назначение | Значение | Примечание |
| --- | --- | --- |
| bg | `#0f172a` | Фон слайда |
| text | `#f8fafc` | Основной текст |
| accent | `#fbbf24` | Выделения, надзаголовок, ключевые числа |
| muted | `#94a3b8` | Второстепенный текст, разделители |
| ... | ... | Дополняй по потребностям темы |

## Типографика

- Заголовочный шрифт: `<stack>` — насыщенность 800–900 для крупных заголовков.
- Основной шрифт: `<stack>` — насыщенность 400–500.
- Подключение веб-шрифта: `<URL таблицы стилей>`. Для системных шрифтов этот пункт не нужен. Правила загрузки — в `references/webfonts.md` навыка `slide-authoring`.
- Изменения размеров шрифта: перечисляй только отличия от стандартных значений `slide-authoring`:
  - Крупный титульный заголовок: 180 px (стандартный диапазон 140–200 ✓).
  - Основной текст: 36 px.

## Макет

- Отступ содержимого от краёв рабочей области 1920 × 1080: 120 px.
- Выравнивание: по левому краю, одна колонка.
- Сетка: при необходимости 12 колонок с промежутками 80 px для слайдов с основным материалом.

## Постоянные компоненты

Компоненты готовы к вставке. Копируй их без изменений в презентацию с этой темой.

### Заголовок (`Title`)

```tsx
const Title = ({ children }: { children: React.ReactNode }) => (
  <h1
    style={{
      fontSize: 140,
      fontWeight: 900,
      lineHeight: 1.05,
      letterSpacing: '-0.02em',
      margin: 0,
      color: '#f8fafc',
    }}
  >
    {children}
  </h1>
);
```

### Нижний колонтитул (`Footer`)

Получай номер слайда через `useSlidePageNumber()`. Никогда не задавай `pageNum` / `total` вручную через свойства.

```tsx
import { useSlidePageNumber } from '@open-slide/core';

const Footer = () => {
  const { current, total } = useSlidePageNumber();
  return (
    <div
      style={{
        position: 'absolute',
        left: 120,
        right: 120,
        bottom: 60,
        display: 'flex',
        justifyContent: 'space-between',
        fontSize: 24,
        color: '#94a3b8',
      }}
    >
      <span>ТЁМНЫЙ ЖУРНАЛЬНЫЙ СТИЛЬ · 2026</span>
      <span>{current} / {total}</span>
    </div>
  );
};
```

### Надзаголовок (`Eyebrow`) и акценты (необязательно)

```tsx
const Eyebrow = ({ children }: { children: React.ReactNode }) => (
  <div style={{ fontSize: 26, letterSpacing: '0.2em', color: '#fbbf24' }}>
    {children}
  </div>
);
```

## Анимация

- Подход: без анимации / сдержанная / насыщенная. Выбери один и объясни одним предложением.
- Готовые ключевые кадры для повторного использования — только для сдержанной или насыщенной анимации:

```css
@keyframes fadeUp {
  from { opacity: 0; transform: translateY(24px); }
  to   { opacity: 1; transform: translateY(0); }
}
```

## Визуальный стиль

Один абзац: впечатление, визуальные источники, ограничения, например «без скруглений, градиентов и декоративных эмодзи». Выбери одно направление: минимализм, максимализм, журнальный стиль, ретро, брутализм, мягкие пастельные тона, неон, бумага и печатная графика.

## Пример использования

```tsx
const Cover: Page = () => (
  <div style={{ width: '100%', height: '100%', background: '#0f172a', color: '#f8fafc', padding: 120, display: 'flex', flexDirection: 'column', justifyContent: 'center' }}>
    <Eyebrow>РАЗДЕЛ 01</Eyebrow>
    <Title>Главная мысль</Title>
    <p style={{ fontSize: 36, color: '#94a3b8', maxWidth: 1200, marginTop: 32 }}>
      Короткий подзаголовок, поясняющий содержание слайда.
    </p>
    <Footer />
  </div>
);
```
````

## Шаг 4б — Создай `themes/<id>.demo.tsx`

Пример имеет ту же структуру, что `slides/<id>/index.tsx`, но находится в `themes/`, поэтому движок использует его только для предпросмотра. Панель Themes импортирует его и отображает внутри `SlideCanvas` размером 1920×1080.

Требования:

- `import { type Page, useSlidePageNumber } from '@open-slide/core';`
- Вставь **те же** компоненты `Title`, `Footer`, `Eyebrow`, что определены в Markdown темы, без изменений, абстракций и импортов из других мест. Пример и документация должны совпадать: пользователь видит то, что `create-slide` перенесёт в презентацию.
- Экспортируй 2–3 компонента `Page` и массив по умолчанию: титульный слайд (`Eyebrow`, `Title`, подзаголовок), слайд с основным текстом и акцентом, заключительный слайд. Возьми за основу раздел «Пример использования» в конце Markdown и дополни его.
- Если полезно впоследствии настраивать параметры темы через Design, также добавь `export const design: DesignSystem = {...}` и `import type { DesignSystem } from '@open-slide/core';`.
- Не импортируй файлы ресурсов, модули из `@/` и вспомогательные компоненты конкретных презентаций, например `WindowShell`. Здесь допустим `@import` таблицы стилей веб-шрифта внутри встроенного `<style>`: это намеренное исключение из `webfonts.md`, поскольку пример монтируется только в панели Themes. Файл примера должен быть самодостаточным.

Каркас:

```tsx
import { type Page, useSlidePageNumber } from '@open-slide/core';

const Title = ({ children }: { children: React.ReactNode }) => (
  // …тот же JSX, что в themes/<id>.md
);
const Footer = () => {
  const { current, total } = useSlidePageNumber();
  // …
};
const Eyebrow = ({ children }: { children: React.ReactNode }) => (
  // …
);

const Cover: Page = () => (
  // …
);
const Content: Page = () => (
  // …
);
const Closer: Page = () => (
  // …
);

export default [Cover, Content, Closer];
```

## Шаг 5 — Проверь результат

Перед завершением проверь:

- [ ] Палитра содержит как минимум `bg` / `text` / `accent` / `muted`, все цвета в HEX.
- [ ] В YAML-заголовке указан `mode`, соответствующий фону палитры.
- [ ] Заданы размеры титульного заголовка, обычных заголовков, основного текста и подписей либо явно указаны стандартные значения `slide-authoring`.
- [ ] Как минимум `Title` и `Footer` представлены готовыми React-компонентами с конкретными встроенными стилями.
- [ ] Раздел «Анимация» задаёт один подход: без анимации, сдержанная или насыщенная.
- [ ] Раздел «Визуальный стиль» описывает одно цельное направление.
- [ ] Созданы оба файла: `themes/<id>.md` и `themes/<id>.demo.tsx`. Презентации и конфигурация не изменены.
- [ ] `.demo.tsx` экспортирует 2–3 слайда и содержит те же компоненты `Title`/`Footer`/`Eyebrow`, что Markdown.
- [ ] `.demo.tsx` соответствует требованиям шага 4б и загрузится в панели **Themes**. Проверь чтением файла, не запускай сервер.

## Шаг 6 — Передай результат

Сообщи пользователю:

- Идентификатор темы и оба пути: `themes/<id>.md`, `themes/<id>.demo.tsx`.
- Что пример появится в панели **Themes** как интерактивная карточка с подробным просмотром. HMR подхватит изменения без перезапуска.
- Что при следующем вызове `/create-slide` тема появится среди вариантов оформления.
- Краткое описание палитры и визуального стиля.

Не запускай сервер разработки. Не меняй реальные презентации даже для демонстрации: для неё предназначен `.demo.tsx`.

## Типичные ошибки

- ❌ Исполняемый код в `themes/<id>.md` за пределами подписанных примеров компонентов. Markdown — документация.
- ❌ Только Markdown без примера или только пример без Markdown. Тема всегда состоит из **обоих файлов**.
- ❌ Использование `themes/<id>.demo.tsx` как реальной презентации. Это только предпросмотр вне списка презентаций; не помещай его в `slides/`.
- ❌ Импорты из `@/` и вспомогательных модулей конкретной презентации в примере. Он должен быть самодостаточным.
- ❌ Выдуманная палитра или шрифты при наличии изображений пользователя или существующей презентации. Извлекай оформление из источников.
- ❌ Изменение `slides/`, `packages/`, `package.json`, `open-slide.config.ts`.
- ❌ Пропуск раздела «Постоянные компоненты». `Title` и `Footer` чаще всего используются повторно и должны быть готовы к вставке.
