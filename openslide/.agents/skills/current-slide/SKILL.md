# Что сейчас открыто у пользователя

Говоря «исправь этот слайд», «поправь этот заголовок» или «слайд, который я смотрю», пользователь обычно не называет идентификатор презентации, номер слайда или элемент. Он имеет в виду текущее содержимое редактора. Прежде чем спрашивать, какой слайд или элемент нужен, проверь файл, который сервер разработки обновляет при каждом переходе и выборе элемента в инспекторе.

## При каждом новом обращении читай файл заново

`current.json` отражает текущую позицию пользователя. Между твоими ответами пользователь свободно меняет презентации, слайды и выбранные элементы, в том числе пока ты занят другой работой. **В начале каждого нового обращения со ссылкой на текущее содержимое заново прочитай файл**, даже если:

- уже читал его в этом чате;
- только что закончил править указанную в нём презентацию;
- сообщение выглядит продолжением: «теперь увеличь», «ещё вот это исправь», «продолжай».

Именно при продолжении пользователь мог перейти на другой слайд или выбрать другой элемент. Старое значение приведёт к незаметному изменению не того файла. Перечитай, сравни `slideId` / `pageIndex` / `selection` с предыдущими значениями и используй новые.

## Как прочитать файл

```
node_modules/.open-slide/current.json
```

Путь указан относительно корня проекта: текущей рабочей папки пользователя, содержащей `slides/` и `package.json`. Прочитай JSON инструментом `Read`.

## Содержимое

```json
{
  "slideId": "q2-roadmap",
  "pageIndex": 2,
  "pageNumber": 3,
  "totalPages": 8,
  "slideTitle": "План развития на второй квартал",
  "view": "slides",
  "pagePath": "slides/q2-roadmap/index.tsx",
  "selection": {
    "line": 42,
    "column": 6,
    "tagName": "h1",
    "text": "План развития на второй квартал"
  },
  "updatedAt": "2026-05-09T14:32:11.123Z"
}
```

- `slideId` — имя каталога в `slides/`, то есть идентификатор презентации. Используй без изменения в API `/__slides/<id>/...` и сегменте URL.
- `pageIndex` — индекс слайда с 0 в массиве `index.tsx`: `export default [Cover, Body, ...]`.
- `pageNumber` — номер слайда с 1 для сообщений пользователю («слайд 3 из 8») и URL `?p=N`.
- `pagePath` — относительный путь к исходному файлу презентации. Передавай непосредственно в `Read` / `Edit`.
- `view` — `"slides"` (просмотр слайда) или `"assets"` (управление ресурсами). При `"assets"` пользователь просматривает файлы презентации.
- `selection` — `null`, если ничего не выбрано. Иначе содержит JSX-элемент, выбранный в инспекторе:
  - `line` с 1 и `column` с 0 указывают на открывающий JSX-тег в `pagePath`. Сопоставляй с исходной строкой, а не с отображаемым DOM.
  - `tagName` — имя отображаемого DOM-тега в нижнем регистре: `"h1"`, `"div"`, `"img"`.
  - `text` — обрезанный фрагмент `textContent` длиной до 120 символов для проверки правильности выбранного узла.
  - Выбор автоматически сбрасывается при переходе в другую презентацию или на другой слайд.
- `updatedAt` — время последнего перехода или смены выделения в формате ISO. Проверяй по нему актуальность.

## Когда использовать

- Пользователь ссылается на текущую презентацию или слайд словами «это», «здесь», «слайд, который открыт», «то, над чем я работаю».
- Пользователь указывает на элемент: «этот заголовок», «эта картинка», «кнопка, на которую я нажал», «сделай компактнее», «измени этот цвет». Если `selection` не `null`, речь об указанном элементе.
- Перед уточнением, какой слайд или элемент нужен.
- До попыток угадать по `git log`, недавно изменённым файлам или последнему каталогу презентации.

## Когда не использовать

- Пользователь прямо назвал презентацию, например «измени `q2-roadmap`»: используй это имя.
- При работе через `apply-comments`: нужный файл уже определяется по маркерам `@slide-comment`.
- Для поиска и перечисления презентаций: читай `slides/` напрямую.

## Проверь актуальность перед правкой

`updatedAt` — время последнего перехода пользователя. Применяй следующие правила:

- **Менее примерно 5 минут назад**: используй данные, открой `pagePath` и внеси правку.
- **Более примерно 5 минут назад**: уточни у пользователя перед изменением. Сервер мог остановиться, пользователь мог переключиться на другую задачу.
- **Несколько часов или дней назад**: игнорируй данные. Спроси, какая презентация нужна.

Если `updatedAt` новее прочитанного в прошлом обращении, пользователь переместился. Переходи к новым `slideId` / `pageIndex` / `selection` без уточнения.

## Если файла нет

- Сервер разработки ещё не открывал презентацию или вообще не запускался.
- Не создавай файл и не угадывай. Спроси, какая презентация нужна, или предложи сначала открыть её на сервере разработки.

## Пример — ссылка на слайд

Пользователь: «уменьши отступы на этом слайде».

1. Прочитай `node_modules/.open-slide/current.json`.
2. Проверь, что `updatedAt` недавний.
3. Прочитай `pagePath`, например `slides/q2-roadmap/index.tsx`.
4. Найди слайд по `pageIndex` в массиве экспорта по умолчанию.
5. Прочитай правила отступов в `slide-authoring`, затем измени этот слайд на месте.
6. Для визуальной проверки сделай снимок `s/<slideId>/preview?p=<pageNumber>` на сервере разработки. См. **«Визуальная проверка слайда»** в `slide-authoring`.

Если `current.json` отсутствует или устарел, спроси: «В какой презентации и на каком слайде нужно уменьшить отступы? Сервер разработки давно не обновлял текущую позицию».

## Пример — ссылка на элемент

Пользователь: «сделай это крупнее».

1. Прочитай `node_modules/.open-slide/current.json`.
2. Если `selection` не `null`, речь об этом элементе. Прочитай `pagePath`, перейди к `selection.line`, найди открывающий JSX-тег рядом с указанной строкой и колонкой. Сверь `selection.text` и `tagName`.
3. Прочитай правила размеров шрифта и макета в `slide-authoring`.
4. Измени JSX-узел на месте.

Если `selection` равен `null`, используй порядок работы для слайда выше. При необходимости спроси, какой элемент нужен: пользователь сослался на него, но не выбрал в инспекторе.
