# Создание и редактирование слайдов OpenSlide

Этот навык — **технический справочник** для `slides/<id>/index.tsx`. Порядок работы задают другие навыки:

- `create-slide` — новая презентация: уточняет задачу, затем использует технические правила отсюда.
- `apply-comments` — обработка маркеров инспектора: находит комментарии и вносит изменения по этим правилам.
- `current-slide` — определение конкретных `slideId` и `pageIndex` по ссылкам «этот слайд», «слайд, который я открыл». Обращайся к нему **сначала**, если пользователь не назвал презентацию, затем возвращайся сюда за правилами редактирования.
- При любой отдельной ручной правке также прочитай этот навык до изменения файла.

Как только требуется писать React-код слайда, используй эти требования как основной источник. Не дублируй их в других навыках — ссылайся сюда.

## Терминология

В инструкциях и ответах пользователю используй естественные русские названия:

- `deck`, `presentation` — **презентация**. Не используй «дек», «слайд-дек» и «колода».
- В API OpenSlide `slide`, `slideId` и каталог `slides/<id>/` часто обозначают **целую презентацию**. Не путай её с отдельным слайдом.
- `page`, `Page`, `pageIndex`, `pageNumber` — **отдельный слайд**; «страница» допустима в контексте печати или PDF.
- `theme` — **тема оформления**. Тема доклада — его содержание, а не оформление.
- `layout` — **макет**; `canvas` — **рабочая область слайда**; `type scale` — **система размеров шрифта**.
- `speaker notes`, `presenter notes` — **заметки докладчика**; `talk track`, `speech script` — **текст выступления**.
- `assets` — **ресурсы** или конкретно **изображения, видео, шрифты**; `placeholder` — **место для изображения**, а не «плейсхолдер».
- `eyebrow` — **надзаголовок**; `footer` — **нижний колонтитул**; `hero title` — **крупный титульный заголовок**.
- `stepped reveals` — **появление по шагам**; `morph` — **плавное преобразование элементов**.

Имена API, свойств, компонентов, команд, файлов и путей сохраняй без перевода. Названия кнопок при необходимости приводи в точности как в интерфейсе с русским пояснением.

## Обязательные правила

- Размещай презентацию в `slides/<kebab-case-id>/`.
- Точка входа — `slides/<id>/index.tsx`. Изображения, видео и шрифты — в `slides/<id>/assets/`.
- **Не изменяй** `package.json`, `open-slide.config.ts` и другие презентации.
- Не добавляй зависимости. Доступны только `react`, `@open-slide/core` и стандартные веб-API.
- Презентация — **один `index.tsx` и каталог `assets/`**. Не создавай соседние `.tsx`/`.ts`, `Card.tsx`, `components/`, `helpers.ts` и т. п. Вспомогательные компоненты и константы размещай в `index.tsx`. Не создавай `README.md` и другие текстовые файлы: заметки докладчика и текст выступления должны быть в экспорте `notes`, см. ниже.

## Требования к файлу

```tsx
// slides/<id>/index.tsx
import type { Page, SlideMeta } from '@open-slide/core';

const Cover: Page = () => <div>…</div>;
const Body: Page = () => <div>…</div>;

export const meta: SlideMeta = {
  title: 'Моя презентация',
  createdAt: '2026-05-16T12:00:00Z',
};
export default [Cover, Body] satisfies Page[];
```

- `export default` — **непустой массив React-компонентов без свойств**, по одному на слайд, в порядке показа.
- Необязательный `meta.title` отображается в заголовке презентации; по умолчанию используется имя каталога.
- Идентификатор презентации — короткое, понятное имя каталога в kebab-case: `q2-roadmap`, `team-offsite-2026`.
- Необязательный `meta.theme` связывает презентацию с темой из `themes/`. Идентификатор должен совпадать с именем `<id>.md` без расширения. На карточке появляется ссылка на тему, а презентация включается в список `/themes/<id>`. Не указывай для презентации без зарегистрированной темы.
- `meta.createdAt` — **строковый литерал ISO 8601**, например `'2026-05-16T12:00:00Z'`, задаваемый один раз при создании. Главная страница использует его для сортировки от новых к старым. Всегда добавляй его в новые презентации: **непосредственно перед записью файла выполни через Bash `node -e "console.log(new Date().toISOString())"` и вставь точный вывод**. Не указывай дату и время по памяти. В самой презентации нужен простой строковый литерал, без `new Date(...)` и импортов: при сборке движок читает значение регулярным выражением, а не выполнением модуля.

## Заметки докладчика (экспорт `notes`)

Движок поддерживает **встроенные заметки докладчика**: необязательный экспорт `notes` в `index.tsx`, индексы которого совпадают с массивом слайдов по умолчанию. Они отображаются в панели заметок, а в режиме показа — в окне докладчика рядом с таймером.

**Если пользователь просит текст выступления, сценарий доклада или заметки на любом языке, записывай их в этот экспорт, никогда в Markdown- или текстовый файл.** Движок не видит `script.md` или `notes.md`; окно докладчика читает только экспорт `notes`.

```tsx
export const notes: (string | undefined)[] = [
  'Начните с цитаты аналитика, затем представьтесь.',
  undefined,
  `Раскройте три основных положения по очереди.
Сделайте паузу для вопросов перед продолжением.`,
];
```

- Одна запись на слайд в порядке массива `export default`. `notes[0]` относится к первому слайду.
- Записи — **обычный текст**: переносы строк сохраняются, Markdown не отображается. Для нескольких строк используй шаблонный литерал, для одной — обычную строку.
- Для слайда без заметок используй `undefined`; завершающие записи `undefined` можно опустить.
- При добавлении, удалении и перестановке слайдов одновременно обновляй порядок `notes`. Иначе смещение индекса незаметно привяжет неверный текст ко всем последующим слайдам.
- Пиши то, что нужно **произнести**: вступления, переходы, упоминаемые числа, подсказки по времени. Не пересказывай экран.

## Изменение существующей презентации

Готовая презентация часто занимает 1000–1800 строк. Если нужна одна страница, **не читай файл целиком**: сначала найди нужный слайд, затем прочитай его диапазон:

```bash
grep -n ": Page = " slides/<id>/index.tsx
```

Команда выводит номера строк всех объявлений `const Foo: Page = …`. Прочитай нужный диапазон инструментом `Read` с `offset` и `limit`: около 150 строк обычно хватает на слайд и вспомогательные компоненты. Весь файл нужен только для общего контекста: проверки палитры, перестановки слайдов, изменения `design`.

## Рабочая область

Каждый слайд отображается в фиксированной области **1920 × 1080**. Движок масштабирует её сам; проектируй так, будто область просмотра имеет именно этот размер.

- Задавай `font-size`, отступы и положение **абсолютными значениями в пикселях**. Не используй `rem`, `vw`/`vh` и проценты для размера шрифта.
- Корень каждого слайда должен заполнять область: `width: '100%'; height: '100%'`.
- Предпочитай встроенный `style={{ … }}`. Загружаемый CSS действует глобально: ограничивай область действия имён классов.

### Размеры шрифта (основа для дальнейшей настройки)

| Элемент | Размер |
| --- | --- |
| Крупный титульный заголовок | 140–200px |
| Заголовок раздела | 80–120px |
| Заголовок обычного слайда | 56–80px |
| Основной текст | 32–44px |
| Подпись или метка | 22–28px |

### Отступы и интервалы

- Отступ содержимого от краёв: **100–160px**. Текст не должен касаться края.
- Межстрочный интервал: 1.2 для заголовков, 1.5–1.7 для основного текста.
- Расстояние между элементами: 32–64px.

### Расчёт высоты — содержимое обязано помещаться в 1080px

Рабочая область **не прокручивается**. Всё ниже 1080px обрезается без предупреждения. До написания JSX рассчитай высоту и проверь размещение. Переполнение — основная причина сломанных слайдов; без расчёта считай риск реальным.

**Полезная высота** = `1080 − top_padding − bottom_padding`. При отступах по 120px сверху и снизу остаётся **840px**, при 160px — **760px**. Сначала выбери отступы, затем размещай содержимое в оставшейся области.

**Высота элемента** = `font_size × line_height × number_of_lines`. Пункт с переносом на две строки считается двумя строками. До следующего элемента прибавь промежуток 32–64px.

**Пример — слайд с основным материалом, отступы 120px, доступно 840px:**

| Элемент | Высота |
| --- | --- |
| Заголовок: 80px × 1.2 × 1 строка | 96px |
| Промежуток | 64px |
| Абзац: 40px × 1.6 × 3 строки | 192px |
| Промежуток | 48px |
| 5 пунктов: 40px × 1.6 × 1 строка | 320px (5 × 64px) |
| 4 промежутка между пунктами по 24px | 96px |
| **Итого** | **816px ✅ помещается в 840px** |

Увеличение заголовка до 120px или шестой пункт уже вызовут переполнение. **Проверяй так каждый слайд до его создания.**

**Правила для отдельного слайда:**

- Заголовок с абзацем **или** заголовок и не более 5 коротких пунктов. Не совмещай длинный абзац и большой список.
- Пункт должен помещаться в одну строку при выбранном размере шрифта. Иначе сократи текст или вынеси на отдельный слайд.
- Титульный слайд с заголовком 140–200px содержит заголовок, один подзаголовок и, возможно, надзаголовок. Больше ничего.
- Заголовку раздела 80–120px почти не нужно дополнительное содержимое.
- Если для размещения приходится менять отступы, уменьшать шрифт ниже нижней границы или межстрочный интервал основного текста ниже 1.4, **раздели на два слайда**. При нехватке места это правильное решение.

**Никогда** не скрывай переполнение через `overflow: auto/scroll`, отрицательные внешние отступы или преобразования. Рабочая область фиксирована; обрезанное содержимое исчезает.

## Визуальный стиль

Выбери цельное оформление и соблюдай его на всех слайдах:

- **Палитра**: один фон, основной цвет текста, акцентный и приглушённый цвета. `bg`/`text`/`accent` размести в `design`, см. «Система оформления». Дополнительные цвета вроде `muted` — обычные константы.
- **Типографика**: один заголовочный и один основной шрифт. По умолчанию системные, если пользователь не указал другие. Насыщенность 800–900 для крупных заголовков, 400–500 для основного текста.
- **Сетка макета**: единый отступ содержимого, например 120px. Выравнивание слева придаёт журнальный характер, по центру — торжественный.
- **Единое направление**: минимализм, максимализм, журнальный стиль, ретро, брутализм, мягкие пастельные тона, неон, бумага и печатная графика. Не смешивай.

Если доступен `frontend-design`, используй его дополнительные рекомендации для выразительного оформления по запросу пользователя.

## Веб-шрифты

Предпочитай системные шрифты. Если нужен фирменный веб-шрифт или поддержка китайского, японского, корейского, тайского, арабского письма, сначала прочитай `references/webfonts.md`. Подключение таблицы стилей внутри компонента регистрирует набор `@font-face` для каждого смонтированного слайда, а для CJK нужно ограничивать набор символов.

## Темы оформления

Если в корне проекта есть `themes/<id>.md` и презентация должна ему следовать, **тема имеет приоритет над стандартными значениями этого навыка**: её палитра, типографика, отступы и компоненты `Title`/`Footer` обязательны. Сначала прочитай файл темы.

Темы создаёт `create-theme`; это документация. Копируй палитру и готовые компоненты `Title` / `Footer` / `Eyebrow` непосредственно в презентацию. Значение `mode: dark` или `mode: light` в YAML-заголовке определяет тёмный или светлый фон, в том числе при выборе варианта логотипа.

## Система оформления (настраивается для каждой презентации)

В начале `index.tsx` можно объявить типизированные параметры `export const design: DesignSystem = { palette, fonts, typeScale, radius }` и использовать их во встроенных стилях через `var(--osd-X)`. Движок добавляет CSS-переменные в корень рабочей области; панель Design позволяет менять их с немедленным предпросмотром.

**Используй по умолчанию.** Каждая новая презентация должна объявлять `design`, чтобы оформление оставалось настраиваемым. Обычные константы палитры допустимы только для разовой презентации с намеренно неизменяемыми цветами. Подробности — в `references/design-system.md`.

До объявления прочитай `references/design-system.md`: полный формат параметров, способы использования `var(--osd-X)` и прямого чтения `design.X`, работа панели и требования к записи через AST.

## Начальный шаблон

```tsx
import type { DesignSystem, Page, SlideMeta } from '@open-slide/core';

export const design: DesignSystem = {
  palette: { bg: '#0f172a', text: '#f8fafc', accent: '#fbbf24' },
  fonts: {
    display: 'system-ui, -apple-system, sans-serif',
    body: 'system-ui, -apple-system, sans-serif',
  },
  typeScale: { hero: 180, body: 40 },
  radius: 12,
};

// Дополнительные цвета и размеры вне DesignSystem остаются обычными константами.
const muted = '#94a3b8';

const fill = {
  width: '100%',
  height: '100%',
  fontFamily: 'var(--osd-font-body)',
} as const;

const Cover: Page = () => (
  <div
    style={{
      ...fill,
      background: 'var(--osd-bg)',
      color: 'var(--osd-text)',
      display: 'flex',
      flexDirection: 'column',
      justifyContent: 'center',
      padding: '0 160px',
    }}
  >
    <div style={{ fontSize: 28, color: 'var(--osd-accent)', letterSpacing: '0.2em' }}>
      РАЗДЕЛ 01
    </div>
    <h1
      style={{
        fontFamily: 'var(--osd-font-display)',
        fontSize: 'var(--osd-size-hero)',
        fontWeight: 900,
        margin: '32px 0',
        lineHeight: 1.05,
      }}
    >
      Главная мысль
    </h1>
    <p style={{ fontSize: 'var(--osd-size-body)', color: muted, maxWidth: 1200 }}>
      Короткий подзаголовок, поясняющий содержание слайда.
    </p>
  </div>
);

const Content: Page = () => (
  <div style={{ ...fill, background: 'var(--osd-bg)', color: 'var(--osd-text)', padding: 120 }}>
    <h2 style={{ fontFamily: 'var(--osd-font-display)', fontSize: 80, fontWeight: 800, margin: 0 }}>
      Заголовок раздела
    </h2>
    <ul style={{ fontSize: 'var(--osd-size-body)', lineHeight: 1.6, marginTop: 64, paddingLeft: 48 }}>
      <li>Одна ясная мысль на строку</li>
      <li>Не более 3–5 пунктов</li>
      <li>Оставляйте свободное пространство</li>
    </ul>
  </div>
);

export const meta: SlideMeta = {
  title: 'Главная мысль',
  createdAt: '2026-05-16T12:00:00Z',
};
export default [Cover, Content] satisfies Page[];
```

## Ресурсы

Ресурсы отдельной презентации размещай в `slides/<id>/assets/` и импортируй как ES-модули: `import hero from './assets/hero.jpg'`. Общие логотипы, аватары и значки — в корневом `assets/` с импортом через `@assets`. Для полностью текстовой презентации не создавай `slides/<id>/assets/`.

Способы импорта (модуль и `new URL(...)`), псевдоним `@assets` и пути ресурсов в темах описаны в `references/assets.md`.

## Места для изображений

Если нужен реальный файл, **который должен предоставить пользователь**, — снимок продукта, фото команды, диаграмма по его данным, — используй типизированный `<ImagePlaceholder hint="…" />` из `@open-slide/core` вместо выдуманного изображения. Пользователь заменит его через панель Assets и инспектор. **Не используй** пустые места для декора или случайных стоковых фото. Если достаточно типографики, макета и цвета, используй их.

Полные правила, размеры и примеры оправданного применения — в `references/assets.md`.

## Номера слайдов

Номер в нижнем колонтитуле (`03 / 12`) получай из `useSlidePageNumber()`. **Никогда не задавай `n` / `TOTAL` вручную**. Требования к хуку и месту вызова — в `references/page-numbers.md`.

## Появление по шагам (`<Steps>` / `<Step>`)

Отложенные части оборачивай в `<Step>`, группу — в `<Steps>`. Каждое `→` раскрывает следующий шаг. Применяй, когда важен **порядок мысли**, а не на каждом слайде. Два обязательных правила: `<Step>` — **непосредственный дочерний элемент** `<Steps>`, иначе он сразу виден целиком; при выборе из сетки обзора слайд должен выглядеть завершённым, поскольку все шаги уже раскрыты.

Перед созданием прочитай `references/steps.md`: порядок нескольких блоков `<Steps>`, схему «заголовок сразу, содержимое по очереди» и зависимость от направления входа. Если есть `slides/build-on-reveal/`, используй его как полный пример.

## Переходы между слайдами

Анимация появления и ухода объявляется через `SlideTransition`: на уровне модуля и с переопределением для слайда. **Приоритет у входящего слайда**. По умолчанию перехода нет: мгновенная смена подходит. Если добавляешь анимацию, сохраняй общий характер движения, длительность 200–280 мс, смещение менее 12 px и изменение масштаба менее 3%. Уходящий слайд остаётся на месте, новый плавно появляется сверху. Движок игнорирует изменение прозрачности `exit`, кроме случая `throughBackground: true`.

До объявления прочитай `references/transitions.md`: типы, принципы оформления, шесть согласованных переходов, ключевые кадры с учётом направления и типичные ошибки.

## Плавное преобразование элементов

Если **один и тот же объект** есть на соседних слайдах, оберни его на обоих в `MorphElement` с одинаковым `id` и включи `morph` в переходе входящего слайда. Положение, размер, скругление и цвета плавно изменятся за одно движение — аналог Magic Move в Keynote. Это средство **непрерывности состояния**: перемещение переключателя, раскрытие карточки, добавление блока в ряд. Не применяй к декору.

Прочитай `references/morph.md` до использования. Там семь проверенных правил: удержание уходящего слайда и изменение только прозрачности входящего, заранее определённая геометрия, отсутствие `transform` на преобразуемом узле, проверка `useIsActivePage()` и другие. Нарушение любого заметно ломает эффект.

## Повторяющиеся элементы: отдельные экземпляры компонента

Для визуально повторяющихся карточек, рядов логотипов, плиток галереи, строк списка, индикаторов шагов **объявляй небольшой компонент и создавай отдельный экземпляр для каждого элемента**. **Не выводи** группу через `array.map` по массиву данных.

Компонент объявляй **в том же `index.tsx`** рядом с компонентами `Page`. Не выноси в `Card.tsx`: презентация всегда состоит из одного `index.tsx` и `assets/`.

```tsx
// ✅ У каждой карточки свой JSX-узел: инспектор меняет их по отдельности.
const Card = ({ src, label }: { src: string; label: string }) => (
  <div style={{ display: 'flex', flexDirection: 'column', gap: 16 }}>
    <img src={src} style={{ width: 320, height: 320, objectFit: 'cover', borderRadius: 12 }} />
    <p style={{ fontSize: 32 }}>{label}</p>
  </div>
);

<div style={{ display: 'grid', gridTemplateColumns: 'repeat(3, 1fr)', gap: 64 }}>
  <Card src={alpha} label="Альфа" />
  <Card src={beta}  label="Бета"  />
  <Card src={gamma} label="Гамма" />
</div>
```

```tsx
// ❌ Один общий шаблон: замена изображения или текста в инспекторе
//    меняет все отображаемые карточки сразу.
const items = [
  { src: alpha, label: 'Альфа' },
  { src: beta,  label: 'Бета'  },
  { src: gamma, label: 'Гамма' },
];
items.map((item) => (
  <div>
    <img src={item.src} />
    <p>{item.label}</p>
  </div>
));
```

Инспектор меняет JSX непосредственно в исходном коде. Тело `map` — **одно место в исходном файле**, общее для всех экземпляров. Замена изображения или подписи там изменяет все карточки сразу. Явные экземпляры дают каждой карточке собственный JSX-узел и свойства, на которые может указать инспектор.

Объявление компонента остаётся общим источником макета и стилей: одна правка обновляет все карточки. Только индивидуальные данные — `src`, `label`, акцентный цвет — задаются при создании экземпляра.

Это правило о повторении **визуального элемента**, а не любых данных. Для обычного текстового списка `<ul><li>` достаточно явной разметки: каждый `<li>` уже отдельный JSX-узел, дополнительный компонент не нужен.

## Встроенное поведение движка

- Главная страница перечисляет каталоги в `slides/`.
- Открытая презентация показывает ленту миниатюр слева, основной слайд, переходы вперёд/назад и счётчик.
- Стрелки, PageUp и PageDown переключают слайды. `F` включает полноэкранный показ.
- При показе Space/→ — вперёд, ← — назад, Esc — выход.
- Изменения `index.tsx` автоматически отображаются в браузере.
- Маршрут разработки `/s/<id>/preview?p=N` показывает один слайд без интерфейса редактора. См. «Визуальная проверка слайда».

## Визуальная проверка слайда

После создания или изменения посмотри на слайд. Расчёт высоты выявляет переполнение, но не конфликт цветов, неудачные переносы и сломанное изображение. При работающем сервере у каждого слайда есть URL предпросмотра без интерфейса редактора. Используй его напрямую, без переходов по главной странице и миниатюрам.

1. **Найди сервер разработки.** Прочитай `node_modules/.open-slide/server.json`: создаётся при запуске, удаляется при остановке.

   ```json
   { "url": "http://localhost:5173/", "port": 5173, "pid": 41234, "startedAt": "…" }
   ```

   Если файла нет, сервер не работает. Не запускай без запроса пользователя; пропусти визуальную проверку и сообщи об этом при передаче результата.

2. **Открой** `<url>s/<slideId>/preview?p=<pageNumber>`, где `p` нумеруется с 1. Для показа только первых `n` шагов добавь `&step=<n>`; по умолчанию всё раскрыто.

3. **Дождись** `[data-osd-preview="ready"]`: шрифты, цели `data-waitfor`, изображения и вступительная анимация должны завершить загрузку или появление. Значение `[data-osd-preview="error"]` означает неизвестную презентацию, номер вне диапазона, ошибку отображения или ожидание дольше 10 секунд: шрифт/изображение не загрузились, цель `data-waitfor` не появилась, анимация продолжается. Текст ошибки — в `[data-osd-preview-error]`. Исправь причину до снимка.

4. **Сделай снимок** с областью просмотра **1920×1080**, чтобы получить исходный размер. Меньшая область уменьшает слайд. Используй доступный инструмент браузера: Playwright, Chrome MCP или другой инструмент автоматизации. Если Playwright уже установлен, можно вызвать CLI; `--no` запрещает `npx` загружать пакет:

   ```bash
   npx --no playwright screenshot --viewport-size "1920,1080" \
     --wait-for-selector '[data-osd-preview="ready"]' \
     "http://localhost:5173/s/<slideId>/preview?p=3" /tmp/<slideId>-p3.png
   ```

   Если инструмента браузера нет, не устанавливай без согласования: пропусти визуальную проверку.

Просмотри снимок и исправь дефекты. Предпросмотр автоматически обновляется и не меняет позицию пользователя в `current.json`.

## Проверка перед завершением

- [ ] `slides/<id>/index.tsx` экспортирует по умолчанию непустой `Page[]`.
- [ ] Корень каждого слайда заполняет `100% × 100%`.
- [ ] Содержимое находится внутри отступов, текст не касается края.
- [ ] **Для каждого слайда сумма (размер шрифта × межстрочный интервал × число строк) + промежутки + 2×отступ ≤ 1080px.** Если места почти нет, раздели слайд. Не используй `overflow: auto` как обход.
- [ ] Ни один пункт списка не переносится на вторую строку при выбранном размере шрифта.
- [ ] Палитра и размеры шрифта единообразны во всей презентации.
- [ ] На верхнем уровне объявлен `export const design: DesignSystem = { … }`, значения используются через `var(--osd-X)`. `design.X` применяется только для числовых вычислений в JavaScript. Пропуск `design` допустим только для разовой презентации с намеренно неизменяемой палитрой.
- [ ] Одна мысль на слайд.
- [ ] Визуально повторяющиеся элементы представлены явными экземплярами `<Component />`, а не `array.map` по списку данных.
- [ ] Все импортированные ресурсы существуют: локальные в `slides/<id>/assets/`, общие в `assets/` с импортом через `@assets/...`.
- [ ] Каждый `<ImagePlaceholder>` соответствует реальному изображению, которое должен предоставить пользователь. Если достаточно типографики или макета, пустое место убрано.
- [ ] Каждый `<Step>` — непосредственный дочерний элемент `<Steps>`. При переходе из сетки обзора слайд выглядит завершённым: при входе вперёд шаги раскрываются, при прямом переходе всё уже видно.
- [ ] Если задан `SlideTransition`, переходы согласованы: 200–280 мс, одинаковые кривые ускорения и замедления, удержание старого слайда и плавное появление нового. Нет задержки появления; `throughBackground` только для намеренного разделения глав. Смещение менее 12 px, изменение масштаба менее 3%. При сомнении переходы убраны. Для `morph` длительность может быть больше, см. `references/morph.md`.
- [ ] При `morph` каждый `id` уникален на слайде и одинаков для пары. Геометрия задана пиксельными константами, не измеряется после монтирования. На преобразуемом узле нет `transform`; вступительная анимация зависит от `useIsActivePage()`.
- [ ] Запрошенный текст выступления находится в `export const notes` с индексами по массиву слайдов, а не в отдельном Markdown- или текстовом файле.
- [ ] При работающем сервере просмотрены все изменённые слайды и исправлены визуальные дефекты. См. «Визуальная проверка слайда».
- [ ] За пределами `slides/<id>/` ничего не изменено.

## Типичные ошибки

- ❌ Сплошной текст. Если на слайде больше примерно 40 слов, раздели его.
- ❌ Основной текст во всю рабочую область без отступов 100–160px.
- ❌ Переполнение высоты 1080px: обрезанное содержимое не видно, нужен отдельный слайд.
- ❌ `overflow: auto` / `overflow: scroll` / `overflow: hidden`, скрывающие избыток содержимого. Рабочая область не прокручивается; ошибка лишь замаскирована.
- ❌ Шрифт ниже нижней границы или отступы меньше 100px ради размещения текста. Раздели содержимое.
- ❌ Пункты списка с переносом на вторую строку. Сократи текст или вынеси пункт на отдельный слайд.
- ❌ Основной текст мельче 28px: не читается с проектора.
- ❌ Несогласованная палитра между слайдами.
- ❌ Установка пакетов: доступны только `react`, `@open-slide/core` и стандартные веб-API.
- ❌ CSS в общем файле. Используй встроенные стили или классы с ограниченной областью действия.
- ❌ `README.md` и другие текстовые файлы в каталоге презентации.
- ❌ Текст выступления отдельным файлом. Окно докладчика читает только экспорт `notes`.
- ❌ Изменение `package.json`, `open-slide.config.ts` или других презентаций.
- ❌ Использование возможности без чтения её справочника. В `references/*.md` перечислены отдельные ошибки: лишние места для загрузки изображений, несогласованные переходы, вложенность `<Step>`, геометрия преобразований.
