# Система оформления (`design` и `var(--osd-X)`)

В начале `index.tsx` презентация может объявить типизированные параметры оформления:

```tsx
import type { DesignSystem, Page } from '@open-slide/core';

export const design: DesignSystem = {
  palette: { bg: '#f7f5f0', text: '#1a1814', accent: '#6d4cff' },
  fonts: {
    display: 'Georgia, "Times New Roman", serif',
    body: '-apple-system, BlinkMacSystemFont, "Inter", system-ui, sans-serif',
  },
  typeScale: { hero: 168, body: 36 },
  radius:    12,
};
```

Используй `export`, а не обычный `const`, чтобы движок прочитал объект и автоматически добавил CSS-переменные в корневой элемент рабочей области.

Набор намеренно минимален: только то, что сейчас меняет панель Design. Остальные параметры — размеры обычных заголовков, отступы, анимация, дополнительные цвета — задавай обычными константами в файле презентации.

## Два способа использования

Оба способа могут встречаться в одной презентации:

- **`var(--osd-X)` для визуальных свойств**: цвета, шрифта, его размера, радиуса скругления. Изменения видны сразу при движении ползунка в панели Design, ещё до записи файла.
  ```tsx
  <div style={{ background: 'var(--osd-bg)', color: 'var(--osd-text)', borderRadius: 'var(--osd-radius)', fontFamily: 'var(--osd-font-body)', fontSize: 'var(--osd-size-body)' }}>
  ```
  Доступны: `--osd-bg`, `--osd-text`, `--osd-accent`, `--osd-font-display`, `--osd-font-body`, `--osd-size-hero`, `--osd-size-body`, `--osd-radius`.

- **Прямое чтение `design.X`**, когда нужно число в JavaScript для вычислений или подписи в интерфейсе. Значения обновляются через HMR после сохранения файла панелью, а не при движении ползунка.
  ```tsx
  <p>{design.typeScale.hero}px</p>
  ```

## Панель Design

Кнопка **Design** находится в заголовке презентации рядом с Inspect. Изменения обновляют черновик в памяти и слой предпросмотра. Плавающая нижняя панель Save / Discard («Сохранить» / «Отменить») сохраняет или отменяет правки. Константа остаётся единственным источником значений; в итоговую сборку попадают сохранённые параметры.

**Используй по умолчанию.** Каждая новая презентация должна объявлять `design`, чтобы оформление оставалось доступным для настройки через панель. Обычные константы в начале файла (`const palette = { bg: …, text: …, accent: … }` с прямыми ссылками в стилях) допустимы только для разовой презентации с намеренно неизменяемой палитрой. Оба подхода могут сосуществовать в проекте: панель работает только с **открытой сейчас** презентацией.

## Требования к формату для записи через AST

- Объявление на верхнем уровне модуля: `export const design: DesignSystem = { … }`, либо вариант с `as DesignSystem` / `satisfies DesignSystem`. Анализатор панели допускает константу без экспорта, но движок читает `design` из экспортов модуля. Без `export` переменные `var(--osd-X)` не определены.
- Инициализатор — объектный литерал с простыми значениями. Без spread-синтаксиса и вызовов вспомогательных функций.
- Импортируй `DesignSystem` из `@open-slide/core`. При создании нового блока панель добавляет импорт автоматически.
