# Появление по шагам (`<Steps>` / `<Step>`)

Показывай содержимое слайда постепенно. Отложенные части оборачивай в `<Step>`, всю группу — в `<Steps>`. Каждое нажатие `→` раскрывает следующий `<Step>`; после последнего переходит к следующему слайду. `←` скрывает последний раскрытый шаг. Так аудитория следует за докладчиком: сначала контекст, затем следствие, затем поворот мысли.

Если в проекте есть `slides/build-on-reveal/` (он включён в демонстрационный проект), изучи его перед созданием слайда с шагами. Иначе достаточно правил и примеров ниже.

```tsx
import { Step, Steps } from '@open-slide/core';

<Steps>
  <Step><div style={BULLET_ROW}>Аудитория читает быстрее, чем говорит докладчик.</div></Step>
  <Step><div style={BULLET_ROW}>Если показать все пункты сразу, их прочтут заранее.</div></Step>
  <Step><div style={BULLET_ROW}>Появление по шагам направляет внимание.</div></Step>
</Steps>
```

## Правила

- **`<Step>` должен быть непосредственным дочерним элементом `<Steps>`.** При большей вложенности или без родительского `<Steps>` содержимое сразу отображается целиком.
- **Остальные дочерние элементы видны сразу.** Размести заголовок или вводный абзац внутри `<Steps>` обычным элементом: он виден с начала, а блоки `<Step>` ждут. Это схема «заголовок сразу, содержимое по очереди»:
  ```tsx
  <Steps>
    <h2>Не всё нужно показывать с задержкой.</h2>{/* видно сразу */}
    <Step><p>Сначала задайте контекст…</p></Step>
    <Step><p>Затем покажите следствие…</p></Step>
  </Steps>
  ```
- **Несколько блоков `<Steps>` на одном слайде раскрываются в порядке документа.** Первый блок проходит все шаги до начала второго; `←` действует в обратном порядке. Так можно сначала раскрыть левую колонку, затем правую, у каждой — свой `<Steps>`:
  ```tsx
  <div style={COL}><Steps><Step>…</Step><Step>…</Step></Steps></div>{/* сначала завершается этот блок */}
  <div style={COL}><Steps><Step>…</Step><Step>…</Step></Steps></div>{/* затем этот */}
  ```
- **Начальное состояние зависит от направления входа.** При переходе вперёд (`→` с предыдущего слайда) содержимое раскрывается с нуля. При выборе через сетку обзора или возврате с более позднего слайда всё содержимое **уже раскрыто**. Слайд должен хорошо выглядеть в обоих случаях: миниатюра и переход из обзора показывают завершённую композицию, а не пустоту.
- **`<Step>` плавно появляется за `duration` миллисекунд, по умолчанию 180.** Для изменения передай `<Step duration={...}>`. При `prefers-reduced-motion: reduce` переход автоматически становится мгновенным; отдельный запасной вариант не нужен.

## Когда применять

Когда важен **порядок мысли**: список с главным последним пунктом, постепенное подведение к выводу, сравнение до/после. Не оборачивай всё подряд в `<Step>`. Титульный слайд, одна цитата или цельная схема лучше воспринимаются сразу. Появление по шагам управляет темпом, поэтому требует той же сдержанности, что переходы.

## Типичные ошибки

- ❌ Появление по шагам на каждом слайде без причины. Оно нужно, когда важен порядок; цельную мысль лучше показывать целиком.
- ❌ `<Step>` не является непосредственным дочерним элементом `<Steps>` или вообще находится без него. Содержимое сразу видно целиком, а поэтапное появление незаметно перестаёт работать.
