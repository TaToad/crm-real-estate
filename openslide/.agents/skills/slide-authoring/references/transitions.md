# Переходы между слайдами (`SlideTransition`)

Движок поддерживает анимацию появления и ухода при смене слайда. **По умолчанию её нет**: слайды сменяются мгновенно, пока не объявлен `SlideTransition`. Это нормальный вариант; добавляй движение только с конкретной целью.

`prefers-reduced-motion: reduce` учитывается автоматически, запасной вариант писать не нужно.

Плавное преобразование общего элемента между двумя слайдами, аналог Magic Move в Keynote, описано в `morph.md` на основе этих же требований.

## Требования

Переход можно задать на уровне модуля для всей презентации и переопределить для отдельного слайда. **Приоритет у входящего слайда**: переход A → B использует `pages[B].transition ?? module.transition`. Его `exit` применяется к A, `enter` — к B. При возврате B → A используется переход A.

```tsx
import type { Page, SlideTransition } from '@open-slide/core';

const Cover: Page = () => <section>…</section>;
const Body:  Page = () => <section>…</section>;

// Стандартный переход модуля: наследуется всеми слайдами без переопределения.
export const transition: SlideTransition = { /* … */ };

// Переопределение для отдельного слайда.
Cover.transition = { /* … */ };

export default [Cover, Body];
```

```ts
type TransitionPhase = {
  keyframes: Keyframe[] | PropertyIndexedKeyframes;  // Ключевые кадры WAAPI
  duration?: number;  // мс (по умолчанию duration верхнего уровня)
  easing?: string;    // Кривая ускорения и замедления CSS
  delay?: number;     // мс
};
type SlideTransition = {
  duration: number;          // Значение по умолчанию верхнего уровня
  easing?: string;           // Значение по умолчанию верхнего уровня
  enter?: TransitionPhase;   // Применяется к входящему слайду
  exit?:  TransitionPhase;   // Применяется к уходящему слайду; opacity удерживается на 1, см. ниже
  morph?: boolean | MorphTransition;  // Преобразование общего элемента, см. morph.md
  throughBackground?: boolean;        // Разрешить исчезновение exit с показом фона --osd-bg
};
type MorphTransition = {
  duration?: number;
  easing?: string;
  delay?: number;
};
```

На обёртке движок также задаёт `--osd-dir` (`1` вперёд, `-1` назад) и `data-osd-dir` (`"forward"` / `"backward"`). Один набор ключевых кадров может учитывать направление без функции JavaScript.

## Порядок слоёв (прочитай до написания `exit`)

Уходящий и входящий слайды находятся в одном контейнере с фоном `--osd-bg`; входящий расположен сверху. Корень каждого слайда заполняет рабочую область и рисует свой фон. Пока уходящий остаётся непрозрачным, **новый плавно появляется над ним, а фон контейнера не виден**.

Если `exit` уменьшает `opacity` до `0`, между исчезновением старого слайда и полным появлением нового виден контейнер. При одинаковом фоне всех слайдов и `--osd-bg` это незаметно. При белом разделе, градиенте или фотографии на весь слайд возникает провал в чёрный или вспышка. Поэтому **движок игнорирует `opacity` в ключевых кадрах `exit`**: уходящий слайд остаётся полностью непрозрачным, а `transform` / `filter` работают.

- Плавное появление задавай в `enter`. Уходящий слайд сохраняй неподвижным либо слегка смещай только через `transform`.
- Не задерживай `enter`: задержка лишь оставляет старый слайд на экране.
- Смещения уходящего слайда делай минимальными или убирай: до появления нового они открывают полоску `--osd-bg` у края.
- Для намеренного перехода через фон, например затемнения между разделами, укажи `throughBackground: true`. Тогда `exit` выполняется как написан. Применяй только между слайдами с общим фоном `--osd-bg`.

## Принципы оформления

Шесть несвязанных переходов в одной презентации создают впечатление случайного набора эффектов. Сохраняй единый ритм.

- **Один характер движения на всю презентацию.** Общий диапазон длительности, одинаковые кривые ускорения и замедления, сохранение старого слайда и плавное появление нового. Различаться может только свойство с небольшим изменением: Y, X, масштаб или размытие.
- **Длительность: 200–280 мс.** Одно значение на весь переход; уходящий слайд удерживается столько же, чтобы слои освободились одновременно. Более 350 мс оставляй для содержательной смены состояния.
- **Максимальное изменение: 12 px или 3% масштаба.** Подъём на 6 px воспринимается как следующая мысль; сдвиг на 1920 px — как другой документ. Движение должно быть едва заметным.
- **В `enter` всегда меняется прозрачность.** Только преобразование выглядит жёстко; изменение одной прозрачности — самый надёжный вариант.
- **Для появления используй `ease-out`**, например `cubic-bezier(0, 0, 0.2, 1)`. Не используй `linear`. Симметричный `ease-in-out` оставляй для преобразований, показывающих смену состояния объекта.

## Шесть согласованных переходов

Возьми этот набор за основу. Выбери один основной переход для презентации; при необходимости второй — для титульных слайдов, третий — для разделителей. Каждый сохраняет уходящий слайд и плавно показывает новый сверху, поэтому фон контейнера не вспыхивает.

```tsx
const EASE_OUT = 'cubic-bezier(0, 0, 0.2, 1)';
const EASE_IN  = 'cubic-bezier(0.4, 0, 1, 1)';
const HOLD: Keyframe[] = [{ opacity: 1 }, { opacity: 1 }];

// RISE — сдержанный основной переход. 6 px по Y. Используй по умолчанию для модуля.
export const transition: SlideTransition = {
  duration: 260,
  exit:  { duration: 260, easing: EASE_IN, keyframes: HOLD },
  enter: { duration: 260, easing: EASE_OUT,
           keyframes: [
             { opacity: 0, transform: 'translateY(6px)' },
             { opacity: 1, transform: 'translateY(0)' },
           ] },
};

// DISSOLVE — только прозрачность. Самый сдержанный вариант.
const dissolve: SlideTransition = {
  duration: 240,
  exit:  { duration: 240, easing: EASE_IN, keyframes: HOLD },
  enter: { duration: 240, easing: EASE_OUT,
           keyframes: [{ opacity: 0 }, { opacity: 1 }] },
};

// SETTLE — для титульного слайда. Подъём и лёгкое размытие только при появлении.
Cover.transition = {
  duration: 280,
  exit:  { duration: 280, easing: EASE_IN, keyframes: HOLD },
  enter: { duration: 280, easing: EASE_OUT,
           keyframes: [
             { opacity: 0, transform: 'translateY(12px)', filter: 'blur(4px)' },
             { opacity: 1, transform: 'translateY(0)',    filter: 'blur(0)'   },
           ] },
};

// BLOOM — масштаб 0.97 → 1, без смещения. Появление на месте.
const bloom: SlideTransition = {
  duration: 240,
  exit:  { duration: 240, easing: EASE_IN, keyframes: HOLD },
  enter: { duration: 240, easing: EASE_OUT,
           keyframes: [
             { opacity: 0, transform: 'scale(0.97)' },
             { opacity: 1, transform: 'scale(1)' },
           ] },
};

// FALL — обратный RISE. Входящий слайд опускается сверху.
const fall: SlideTransition = {
  duration: 260,
  exit:  { duration: 260, easing: EASE_IN, keyframes: HOLD },
  enter: { duration: 260, easing: EASE_OUT,
           keyframes: [
             { opacity: 0, transform: 'translateY(-6px)' },
             { opacity: 1, transform: 'translateY(0)' },
           ] },
};

// BREATH — разделитель. Полный уход, пауза 120 мс, затем появление.
// Этот переход намеренно показывает --osd-bg, поэтому включает
// `throughBackground`. Применяй только между слайдами с общим фоном презентации
// и не более 1–2 раз на презентацию.
const breath: SlideTransition = {
  duration: 460,
  throughBackground: true,
  exit:  { duration: 180, easing: EASE_IN,
           keyframes: [{ opacity: 1 }, { opacity: 0 }] },
  enter: { duration: 240, delay: 300, easing: EASE_OUT,
           keyframes: [
             { opacity: 0, transform: 'translateY(8px)' },
             { opacity: 1, transform: 'translateY(0)' },
           ] },
};
```

Все шесть имеют общий характер и отличаются только свойством небольшого изменения. Получается разнообразие при едином оформлении.

## Ключевые кадры с учётом направления (применяй редко)

Обычно при возврате не нужно зеркально менять движение. Если это необходимо, например для горизонтального смещения, используй `--osd-dir` внутри `calc()`:

```tsx
{ transform: 'translateX(calc(var(--osd-dir, 1) * 8px))' },
{ transform: 'translateX(0)' },
```

Если это требуется каждому переходу, оформление, вероятно, перегружено. По умолчанию движение вперёд и назад одинаково.

## Типичные ошибки

- ❌ Уменьшение `opacity` в `exit` до `0` с задержкой `enter`. Движок игнорирует исчезновение, и старый слайд просто стоит на месте. С `throughBackground: true` возникает вспышка фона контейнера. Вместо этого удерживай старый слайд.
- ❌ `throughBackground: true` в основном переходе или между слайдами с разными фонами: каждая смена проваливается в чёрный.
- ❌ Шесть разных переходов на шести слайдах: оформление выглядит случайным.
- ❌ Выезд сбоку через `translateX(100%)`: напоминает модальное окно iOS или эффект Push в PowerPoint.
- ❌ Резкое увеличение, например `0.85 → 1`, с размытием: похоже на открытие фото и подразумевает приближение к объекту.
- ❌ Раскрытие через `clip-path: inset(…)`: театральный эффект в духе After Effects.
- ❌ Одновременное размытие обоих слоёв: глазу не на чем сосредоточиться.
- ❌ Длительность обычной смены более 350 мс: затянуто.
- ❌ Смещение более 12 px или изменение масштаба более 3%: нарушает связность.
- ❌ `linear`: механическое движение.
- ❌ Переходы в каждой презентации без причины. **Если нет ясной цели, не добавляй их.** Мгновенная смена подходит.
